## Version 2.0 — Custom Design Commerce & Design Persistence

**فاز دوم پروژه از این نقطه آغاز می‌شود و معماری تجاری و الگوریتم ذخیره‌سازی طراحی مرجع این مرحله است.**

- طراحی از محصول مشخص مستقل می‌شود و هر طراحی شناسه یکتای خودش را دارد.
- قیمت پایه طراحی و قیمت لیبل‌ها باید مستقل و قابل تنظیم باشند.
- دکمه «ذخیره طراحی» مسیر خرید نیست؛ پایان جریان طراحی با «افزودن به سبد خرید» خواهد بود.
- تا قبل از پرداخت، داده‌های طراحی در وضعیت موقت/سبد باقی می‌مانند و طرح نهایی سفارش فقط پس از پرداخت موفق تثبیت می‌شود.
- طراحی نهایی باید علاوه بر شناسه لیبل‌ها، متن‌های کاربر، اندازه، موقعیت، زاویه، لایه، نما/سمت و سایر پارامترهای لازم را به‌صورت ساختاریافته نگهداری کند.
- برای هر نما، خروجی دوبعدی نهایی طراحی نیز باید قابل بازسازی و نگهداری باشد تا دقیقاً مشخص باشد چه چیزی، با چه اندازه و زاویه‌ای، روی لباس قرار گرفته است.
- فایل‌های کاربر نباید به‌عنوان داده خام و بی‌ساختار داخل دیتابیس ذخیره شوند؛ فایل و متادیتای طراحی باید از هم تفکیک شوند.
- قیمت‌ها باید از پنل مدیریت در ادامه قابل تنظیم باشند.
